# DB seed data

`packages/db` の開発用 seed は、チケット販売の代表的なイベント形状をシナリオ単位で作る。

実行コマンド:

```sh
bun run db:push   # スキーマを反映しつつDBを空にする（--force-reset）
bun run db:seed
```

seed は空のDBに対して実行する前提で作っている。同じDBに2回実行すると、シナリオが固定値で作る購入者のメールアドレスが衝突して失敗する。作り直したいときは `db:push` からやり直す。

## 構成

- [`packages/db/src/seed/run.ts`](../packages/db/src/seed/run.ts): エントリーポイント。登録済みシナリオを順に実行して結果を表示するだけの薄いファイル。
- `packages/db/src/seed/senarios/<受付方式>/<販売方式>/<パターン>.ts`: 実際のデータ作成。1ファイル1シナリオで、ファイル名がそのままパターン（公演数・在庫種別数・受付回数・料金種別数など）を表す。

各シナリオは `seed()` を export し、自分で1トランザクションを張る。途中のシナリオが失敗しても、そのシナリオのデータだけが巻き戻り、成功済みのシナリオは残る。

## 実装済みのシナリオ

- `entry-number/first-come/1stage-2inventory-category-1sale-window.ts`
  - 1公演 / S席20枠・A席50枠の2在庫種別 / 先着の1販売受付
  - 整理番号の接頭辞は S席→`S`、A席→`A`（ADR 0008）
  - 購入者1がS席2枚をカード決済（入金済み・発券済み・`S-1` / `S-2`）
  - 購入者2がA席1枚をコンビニ払い（入金待ち・未発券・`A-1`）

ファイル名だけ用意して中身が空のシナリオは、まだ実装していないパターンの置き場所として残してある。

## シナリオを追加するとき

1. `senarios/<受付方式>/<販売方式>/` に1ファイル追加し、`seed()` を export する。
2. `run.ts` の `seedScenarios` に1件登録する（バレルimportは禁止なので直接importする）。
3. このドキュメントの「実装済みのシナリオ」に、作られる状態を1件追記する。
